**API の通し ② の 8 件（NG 5・注意 3）は、どれも仕様どおりである**（検証のスクリプトの前提が古い）。

- リフレッシュトークンは 1 日に 1 回だけ入れ替わる（[機能一覧](features.md) 1.2）。1 日以内のリフレッシュは同じトークンのまま 200 になる。スクリプトは毎回入れ替わる前提だった
- ログインに失敗した直後は、アカウントごとに 1 秒照合しない（`apps/api/src/auth/login-backoff.ts`）。スクリプトは、再設定の直後に古いパスワードで失敗した直後、間を空けずに新しいパスワードで入ろうとした。1.1 秒待てば 200 になることを別に確かめた
- 削除済みの id への既読は 404・アーカイブで名前が `-n` 付きに変わる・同じ発行の二度目の確定は同じ結果を返す（冪等）。どれも仕様であり、スクリプトの前提を外した確認で OK になった
- 再設定の前のアクセストークンは、期限（15 分）まで使える。[機能一覧](features.md) 1.1 の代償のとおり

**画面の通しの残り（場面 11・18）は、検証のスクリプトの問題である。** メッセージの一覧は画面に入る分だけを DOM に描く（react-virtuoso）ため、下に押しやられた投稿はスクロールするまで DOM に無く、スクリプトが押せずに時間切れになった。一覧をホイールでスクロールしてから押すと、編集・削除・ピン留めとも、画面と API の両方で OK だった（ステージングと本番の両方）。

## 未解決

- **デプロイの入れ替えの間に、リアルタイムの配信が別のタスクの利用者に届かなかった疑い**（#695）。ステージングの画面の通しの 1 回目で、あおいの投稿がれんの画面に 15 秒出なかった（DB には残り、読み直せば出る）。CD のデプロイで古い 2 タスクが止まった時刻と重なる。新しいタスクは 1 分以内に Valkey につながっていた（ElastiCache の接続数から）。その後の再現の確認（ソケットで 20 回・画面で 5 回・通しの 3 回目・本番の通し）では起きていない。api は HTTP の要求ごとのログを出さないため、投稿をどのタスクが受けたかは分からず、原因は特定できていない

## 検証を進めるうえで当たったこと

- 検証のためのログインを重ね、発信元ごとのログインの制限（15 分に 20 回）に 2 回当たった。登録の制限（1 時間に 10 回）もあるため、実環境の通しはログインと登録の回数を数え、枠をまたいで並べる必要がある
- PowerShell で `bash` と打つと WSL の bash が起動し、PowerShell の環境変数が渡らない。`scripts/release.sh` は Git Bash を名指しして流した（`& "C:\Program Files\Git\bin\bash.exe" scripts/release.sh`。`$env:MSYS2_ARG_CONV_EXCL = "*"` を付ける）
- AWS CLI（Windows）は、日本語を含む paramfile を既定の文字コードで読めない（`AWS_CLI_FILE_ENCODING=UTF-8` が要る）
